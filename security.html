NOTA — Information Security Policy

Last updated: June 16, 2026

This Information Security Policy describes the administrative, technical, and organizational measures NOTA ("we", "us", or "our") uses to protect the confidentiality, integrity, and availability of consumer data, including financial data accessed through Plaid. NOTA is operated by Hlib Ladin, an individual developer based in Calgary, Alberta, Canada.

1. Governance and Risk Management

  • Security owner: Hlib Ladin is the individual responsible for information security and serves as the point of contact for all security and privacy matters (bbs7755@gmail.com).
  • This policy is documented, operationalized, and reviewed at least annually, or sooner when material changes occur to the application, infrastructure, or applicable regulations.
  • We follow a risk-based approach: data flows handling consumer financial data are identified, and controls are applied to minimize the amount of data collected, stored, and retained (data minimization).

2. Identity and Access Management

  • Least privilege: Access to production systems and sensitive data is limited to the security owner only, on a strict need-to-know basis.
  • Row-Level Security (RLS): All consumer data is stored in a Supabase (PostgreSQL) database protected by row-level security policies, so each end user can access only their own records. Application requests are scoped to the authenticated user.
  • Multi-factor authentication (MFA): MFA is enabled on all administrative accounts that can access systems storing or processing consumer financial data, including the cloud database provider, source-code repository, build platform, and email.
  • Secrets management: API keys, service-role keys, and the Plaid client secret are stored as protected environment variables / managed secrets and are never committed to source control or shipped in the client application.

3. Infrastructure and Network Security

  • Encryption in transit: All communication between clients, our backend, and third-party services is encrypted using TLS 1.2 or higher.
  • Encryption at rest: Consumer data, including data received from the Plaid API, is encrypted at rest (AES-256) by our managed database provider (Supabase).
  • Managed infrastructure: Our backend runs on Supabase managed infrastructure, which provides network isolation, automated security patching, and infrastructure-level monitoring.
  • Credential handling: Bank login credentials are entered by the user directly within Plaid Link and are never transmitted to or stored on our systems. We receive only Plaid access tokens and the financial data required to operate the app.

4. Development and Vulnerability Management

  • Dependency scanning: Third-party dependencies are monitored for known vulnerabilities using automated tooling (e.g., Dependabot / npm audit), and vulnerable packages are patched promptly.
  • Patch management and SLA: Production infrastructure is automatically patched by our managed provider; developer machines are kept up to date with operating-system and application security updates. Identified vulnerabilities are remediated within a defined service-level target: critical and high-severity issues within 7 days, and medium/low-severity issues within 30 days, where a patch or mitigation is available.
  • End-of-life (EOL) software: We actively monitor the runtime, framework, and dependency versions in use (e.g., Expo SDK, libraries) and upgrade away from end-of-life or unsupported versions to remain on supported, patched releases.
  • Secure development: Secrets are excluded from source control, code changes are reviewed before release, and least-privilege principles are applied to API access.

5. Data Protection and Privacy

  • We maintain a public Privacy Policy describing what data we collect, how it is used, and the rights available to users: privacy policy.
  • We obtain consent from consumers for the collection, processing, and storage of their data, including explicit consent before a bank account is connected through Plaid.
  • We maintain and enforce a data retention and deletion policy in compliance with applicable privacy laws (PIPEDA, GDPR, CCPA). Users can delete their data at any time from within the app, and disconnecting a bank removes the associated Plaid data.
  • We do not sell consumer data, and we do not use consumer financial data to train AI models.

6. Incident Response

  • Suspected security incidents are investigated promptly by the security owner.
  • In the event of a confirmed breach affecting consumer data, we will contain the issue, assess impact, remediate, and notify affected users and relevant parties (including Plaid and regulators where required) in accordance with applicable law.
  • As of the date above, NOTA has not experienced a data breach.
