NOTA — Access Control Policy

Last updated: June 16, 2026 · Owner: Hlib Ladin · Calgary, Alberta, Canada · bbs7755@gmail.com

1. Purpose and Scope

This Access Control Policy defines how NOTA ("we", "us", or "our") controls and limits access to production assets and sensitive consumer data, including financial data accessed through Plaid. It applies to all systems that store, process, or transmit consumer data, and to all individuals with access to those systems. NOTA is operated by Hlib Ladin, an individual developer based in Calgary, Alberta, Canada.

2. Principle of Least Privilege

  • Access to production systems and sensitive data is granted strictly on a need-to-know basis.
  • Access is currently limited to the security owner (Hlib Ladin), who is the sole operator of the application and its infrastructure.
  • No third party is granted standing access to production consumer data.

3. Role-Based Access Control (RBAC)

  • End-user data isolation: Consumer data is stored in a Supabase (PostgreSQL) database with row-level security (RLS) policies, ensuring each authenticated end user can access only their own records.
  • Service roles: Backend operations use scoped service roles with the minimum permissions required. Privileged keys (e.g., service-role keys, Plaid client secret) are restricted to server-side environments.

4. Authentication

  • Administrative access: All administrative accounts that can access systems storing or processing consumer financial data (cloud database provider, source-code repository, build platform, email) are protected with multi-factor authentication (MFA).
  • Non-human authentication: Service-to-service and API access is authenticated using OAuth tokens and TLS certificates. Credentials are stored as managed secrets / protected environment variables and are never committed to source control or shipped in the client app.
  • End-user authentication: End users authenticate through Supabase Auth (email/password or Google OAuth). Bank credentials are entered directly within Plaid Link and are never received or stored by us.

5. Access Provisioning and Review

  • Access is provisioned only when required to operate or maintain the service.
  • Access rights are reviewed at least annually, and immediately upon any change in personnel or third-party relationships, with unnecessary access revoked promptly.
  • Should additional personnel be onboarded in the future, access will be granted per role and revoked upon role change or departure.

6. Monitoring and Enforcement

Access to managed infrastructure is logged by our providers. Suspected unauthorized access is investigated promptly by the security owner. This policy is reviewed at least annually and is enforced as part of NOTA's overall Information Security Policy (https://lilg1488.github.io/nota-legal/security.html).
